# 背包连续整理

此前手动整理时，拿起会把焦点交给背包Grid，取消却没有交还按钮；成功事务重建页面时，又从没有焦点标识的Grid回退到第一件商品。装符还会消耗当前松散符文UID，使详情错误回退到首件物品。

本轮按实际结果UID衔接选择、详情与焦点，让连续整理经过原库存事务。

| 操作结果 | 选择与焦点 |
| --- | --- |
| 手动放置成功 | 原物品的“拿起 / 移动” |
| B／Esc取消手动持物 | 原物品的“拿起 / 移动”，物品保持原位 |
| 合成成功 | 保留下来的目标物品及其“拿起 / 移动” |
| 装符／换符成功 | 实际目标武器及其“拿起 / 移动”，清除旧松散符文选择 |
| 拆符成功 | 原武器及其“拿起 / 移动” |
| 出售成功 | 售后列表中原位置的物品；超过列表尾部则选末件，退回的符文也参与选择，聚焦其“拿起 / 移动” |
| 扩容成功 | 持物时继续原物品、游标和旋转；空闲时保留扩容按钮，扩满后回选中物品的拿起按钮 |

A或Enter放下后，松开不会自动再次拿起；下一次主动按下才继续。无效落点保留持物、游标与Grid焦点；事务拒绝时保留原操作入口及原有库存回滚规则。键盘取消不会用空预览覆盖“已取消整理”提示。

显式用户取消与事务成功、购买、模态、换屏、原生拖拽等内部清理分别处理。用户取消在当前有效页面同步交还拿起焦点，不额外排队延迟请求。从持物打开暂停／设置会取消预览，关闭后恢复到对应拿起按钮。

商店重建的延迟恢复绑定本次页面代次，旧代次、等待重建、覆盖层或引擎拖拽期间不恢复底层焦点。鼠标原生拖拽沿用松手规则，成功后请求结果盒子焦点；取消拖拽不额外跳到拿起按钮。没有重新开始拖拽或改写原payload、抓取偏移及事务信号参数。

专项每条连续操作链只在开头定位一次焦点，之后使用解析键盘／手柄事件，不用测试中的重新选择或抓焦点修补流程。库存通过正式购买、扩容与合成构造，预览不读写个人档案；独立测试预算、冻结战斗与软件事件不代表实体手柄或自然对局难度。

## Windows结果

基于`399ad9a`，最小连续链在旧源码上32条断言有15条失败；最终扩展专项headless97条、原生126条全部通过。涵盖两轮不补焦点的移动、B／Esc取消、合成、装符与直接详情动作，以及拆符、出售退符、扩容持物、信号重入、模态来源和旧代次恢复。新页面保留相同UID时，旧代次的真实延迟恢复仍不能改变新焦点。

原生GUI拖放使用引擎`warp_mouse()`同步实际Windows光标，再发送解析鼠标事件。初次仅注入事件时，系统光标仍在另一位置，原生抓取偏移和松手位置因此错误；该失败保留本地日志，未据此修改生产落放规则。最终在实际(2,2)目标上由引擎处理松手，正式库存提交、引擎拖拽结束和结果盒子焦点均通过；中止拖拽保持库存且不延后跳到拿起按钮。该过程仍是软件输入，不是实体鼠标或手柄验收。

`./tools/test.sh`包含80套Godot与5个档案入口，共29456条断言、32项Python测试通过。既有背包、手柄、模态、设备提示和肩键阅读另做原生回归，Bash与PowerShell入口语法检查通过。

四组1280×720预览分别完成移动、合成、装符和取消，再实际A拿起、B取消回结果物品；钱包与随机状态保持。截图等待真实提示计时器自然结束，完成独立复核；不据此扩大为新的960×540截图验证。

Windows实际EXE冒烟及匹配引擎加载导出PCK的126条原生专项通过，PCK外部夹具与普通EXE启动分别记录。四组源码／PCK预览逐字节一致，ZIP的CRC、5成员字节和x64 PE通过；434个既有素材、数据与历史报告文件保持，51项美术／音效不变，上版ZIP保留。当前证据和源码指纹见[验收记录](../reports/backpack-focus/validation.json)。

本轮只改界面输入与焦点，core、combat和data文件保持原字节；未重新运行完整自动对局、采集压力性能或重建macOS。实体手柄仍待实机验证。
