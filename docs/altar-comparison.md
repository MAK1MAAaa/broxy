# 祭坛购前对照与尾迹收敛

本轮继续暗黑秘术方向，改善复合遗物的选择信息和密集战斗的轮廓辨识。七种法器、十种遗物、价格、随机池、符文规则及机器人策略保持。

## 遗物购前对照

遗物商品的购买按钮旁增加“对照”。它直接读取当前构筑，显示当前与假设购买后的属性、实际补血、层数、余额，以及每个已装备法器的每枚伤害和标称间隔。正面与负面变化都使用文字标记，配合冷青和灰红；直接购买继续使用原按钮。

例如持有一层血棘与一层时砂时，裂砂漏将伤害倍率从×1.15变为×1.09、攻速从×1.12变为×1.34，星陨每枚伤害62.1→58.9、标称间隔约1.384→1.157秒。骨盾印在20/100生命时预览为32/112。小数差值标“约”，避免两端数值与差值分别舍入后看起来减法不符。数值计入现有强化和遗物，未计符文追加命中，不作为实战DPS。

`RunState.relic_purchase_preview(index)`是纯查询。它与正式交易共享属性聚合和生命上限差值计算，复用`purchase_error()`；查询不扣款、不增加层数、不发出`changed`、不分配符文UID，也不消耗随机数。缺钱时仍能查看效果，并明确标出缺额；已售或满3层时保持现有构筑，不显示第四层。

对照层使用现有旧金角框、独立遗物图标与有界表格滚动区。Tab/Enter打开，Esc或返回按钮恢复来源焦点；PageUp/PageDown/Home/End可滚动表格。底层购买、改装及刷新动作在弹层打开时隔离；正式状态变化或商店重建会关闭旧对照，旧epoch按钮不能打开新报价。

## 友方尾迹

此前霜矛与星陨等法器使用完全不透明的宽尾迹，在密集固定压力场景中遮住先绘制的暗色敌人。`arsenal-lines-v3` / `subdued-trails-v1`保持端点、拖尾长度、核心、月弧、电角、星芒、贯穿翼线、弹射环及危险信息顺序，仅收敛非幽焰尾迹：

| 层 | 此前 | 本轮 |
| --- | --- | --- |
| 主体透明度 | 1.0 | 0.58 |
| 主体宽度 / 基础宽度 | 1.0 | 0.72 |
| 外晕透明度 | 0.20 | 0.10 |
| 外晕宽度 / 基础宽度 | 2.33 | 1.55 |

幽焰保留原0.40透明度的单尾迹。样式按已有法器/符文家族复用，不新增逐弹几何、纹理、GPU实例或绘制批次；静态SVG/WAV仍为42项、`engraved-05`。外观优化不改变命中、伤害、碰撞或模拟RNG。

## 复现

```sh
./tools/test.sh
./tools/run.sh --script res://tools/preview_relic_comparison.gd -- --case=tradeoff --capture=res://reports/altar/tradeoff.png
./tools/run.sh --script res://tools/preview_trail_readability.gd -- --variant=after --density=dense --capture=res://reports/altar/trails-dense-after.png
./tools/run.sh -- --benchmark --benchmark-content --seconds=300
```

遗物夹具另支持`bulwark`、`capped`、`poor`。尾迹夹具另支持`sparse`；`before`需要本地保存的前版Painter快照，缺少快照时明确失败，发行包不依赖此文件。Windows可改用`tools/run.ps1`并把用户参数分隔符写成`'--'`。这些都是明确标注的固定陈列，不写个人档案，不代表自然对局或真人难度。

性能入口默认覆盖`reports/performance.json`，需先备份再另存本轮结果；历史macOS、Windows与上一轮内容记录保持。原始截图、日志与30局逐条输出留在本地`reports/altar/`，紧凑验收及配对摘要纳入源码。

## 本轮验证

Windows 11、Godot 4.7.2原生引擎执行完整`./tools/test.sh`：29次套件调用共6783条Godot断言和22项Python测试通过。遗物纯查询专项3483条覆盖全部10种遗物、0/1/2层与六类强化叠加，逐项对照独立夹具的真实购买；另覆盖缺钱、已售、满层、非法输入、同属性合并及状态/RNG/UID/信号不变。原生购前对照UI50条验证真实Enter、鼠标、Esc、PageDown滚动、来源焦点恢复、底层拦截与失效商品；尾迹151条覆盖28种法器/符文状态、真实碰撞纯度及实例/提交预算。

四张1280×720原生对照图核对裂砂漏、骨盾印、满层与缺钱；四槽法器最后一行可通过明确的滚动区查看，未声称单屏同时展示所有说明。稀疏/密集尾迹使用同seed20261024和20次正式模拟步，前后模拟哈希、端点哈希、命中及实例记录一致；稀疏4次直接/1次追加命中，密集2918次直接/5146次追加命中。密集陈列额外叠加了标注的右下危险夹具，因此截图为302敌人、601枚友弹，不与正式300/600压力采样混称。

固定竞技场ROI中灰度≥180的像素，稀疏3549→3187、密集126230→108780；稀疏主角区域和真实敌弹中心3×3像素保持相同。统计仅说明该静帧的高亮面积减小；前后图已核对弹头、新法器图形及危险层，仍不证明动态战斗或真人辨识率。原始哈希与读回统计见`reports/altar/visual-comparison.json`。

同seed2026—2035×三类符文的30局完成，23胜7败。新核心`prototype-0.1.0+15a5ba98e084`与前版`7b6edecdab6b`除`balance_version`字段外，完整输出逐字段一致，包括购物trace和报价观测，见`reports/altar/simulation-comparison.json`。该结果证明所测样本的规则和轨迹未变；旧机器人仍不采购四件新遗物，不能代替真人购物选择或新遗物整局平衡验证。

最终七法器场景采用5秒预热＋300秒正式采样：18,363帧，平均61.204 FPS、P99 28.260ms，达到≥58 FPS／≤33ms门槛，退出0。末尾300敌人、600弹体、200掉落，七件法器均产生实际伤害；主/次命中314,665／1,417,048，刻痕池峰值32、末段10批，尾迹版本`arsenal-lines-v3`。默认设置、不保存个人档案，采样期间未同时执行Godot测试、构建或模拟，120秒读取一次真实视口截图；帧间隔包含该截图，不是GPU耗时。七来源/三符文参与补充，不保证21个组合全程同时存在。结果见`reports/altar/performance.json`和`validation.json`；与前版种子不同，不把帧率差额当作尾迹优化的独立收益，也不推广为所有构筑或设备的性能。

Windows release导出与实际EXE图形启动通过，ZIP保留引擎许可。上一轮内容版ZIP另存`build/Embers-windows-before-altar-78e3f86.zip`；最新包为`build/Embers-windows-x86_64.zip`。macOS构建依赖macOS系统工具，本机未重跑；静态42项素材未改变，既有跨平台入口保留。
