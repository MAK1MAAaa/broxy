## 装备者与受益角色

新增五件购买或起手入包时明确归属于主角，使用`owner_ref = {kind: main}`，目前不能转交后排。杜兰德尔与十字弓的自身加成只进入主角属性，后排施法不会继承这两件的主角专属攻击或技伤。杜兰德尔提高生命上限不会回复生命；合成、出售也不会制造回复事件，上限下降时当前生命按新上限裁定。

队伍效果再按实际角色筛选。半月拳刃作用于火主角，以及背包中实际存在的火后排；谎言之书只作用于实际暗角色。武器图标、武器元素、物品格数与可选主角总数都不参与角色属性或人数判定。后排以技能物品UID识别，移动与旋转保留身份，出售后不再受益。

七位主角覆盖火、风、水、暗：阿尔克、克拉莉丝、花火、娜希尔为火，希尔媞为风，莫迪亚迦为水，法露伽为暗。当前后排仍只有克拉莉丝、花火、希尔媞；三位新主角没有自动变成后排。因此谎言之书目前可增强暗主角法露伽，没有虚构暗属性后排。零伤害的秘术脉冲仍保持零伤害。

商店、库存详情、合成与出售预览使用相同库存投影，展示装备者头像与实际受益角色的技能数值。已开始施放的技能锁定当次参数；中途购买、出售或合成只改变后续施放，持续区与已发出的炸弹不会重新套用新属性。

背包阶级不映射原作装备等级或觉醒。固定JP表中，十字弓的基础技伤为47.5%→95%，另有原觉醒5的＋35%；谎言之书与半月拳刃的基础效果为22.5%→45%，另有原觉醒5的＋15%。这些觉醒行已经保留和核对，但没有因为合成到Ⅲ阶而自动解锁。杜兰德尔的原攻击＋160%与生命＋15%分属独立规则；本作后续阶级的倍率是明确适配。

装备语义核准现为21件／44条基础规则；405件／842条基础规则及全部108条增强规则仍未取得完整语义支持。`equipment_rules.json`的解码支持与Godot实装分别追踪，旧16件的语义研究见[前轮核对记录](wf-equipment-semantics.md)。当前21件武器包含历史外观映射与改编效果，不表示21件原作能力均已完整复现。

## 老旧法杖的施法叠层

主角一次成功R施放为每件有效法杖增加一层，最多4层。冷却未结束、角色死亡、技能容量不足或施放提交失败时不叠层；后排Q／E、多段命中、持续伤害和五颗炸弹不会额外叠层。本项目选择让这次R直接使用新增层数，随后施放的后排技能也取得当时已生效的队伍技伤。

原JP能力行和说明能够证明“装备者施法使队伍技伤叠层”，尚不能证明其原引擎相对于当次伤害参数捕获的执行顺序。**本次施放立即享受新增层数、按波次重置，均是本项目明确采用的规则，不声称原作执行顺序相同。**

叠层按武器UID保存，移动、旋转及暂停不重置；合成保留目标UID已经取得的层数，并使用新阶级强度，源物品的层数不转移。出售立即撤销该UID对后续施放的加成，同名新购武器从零层开始。真正进入新波后归零；已锁定的持续技能伤害不随改装变化。

## 原图来源与重建

独立[来源清单](../tools/world_flipper_scoped_equipment.json)按原作numeric ID、dev名、资源引用和原能力行SHA绑定五件身份；中文名称使用已锁定版本的BWIKI别名。十字弓、杜兰德尔、谎言之书、老旧法杖取自Wiki原生透明像素图，尺寸分别为18×18、22×22、15×18、18×18。

半月拳刃取自[公开JP缓存归档](https://archive.org/details/gacha-archive)的原`item/sprite_sheet.png`与AMF3 atlas，精确帧名为`item/equipment/general/fist_0006`。18×18裁片按原`fx/fy/fw/fh`恢复20×20画布；未使用同名能力魂Core或带图鉴背景的图片。只将原PNG签名字母`png`恢复为`PNG`用于解码，原下载字节与SHA另行保留。

五张原图均以完整画布2倍nearest居中放入64×64，输出及像素SHA记录在[equipment/manifest.json](../assets/worldflipper/equipment/manifest.json)。旧94张运行PNG保持，五张新图独立存放。缓存元数据声明1.780.30，不证明半月拳刃图集的逐对象版本或最终1.780.40字节一致性；归档范围见[JP归档说明](world-flipper-jp-archive.md)。

需要Python 3.10+与Pillow。原始下载保留在忽略目录`.tools/wf-scoped-equipment/raw/`，首次准备去掉`--offline`；完整ZIP不需要下载。

```powershell

python -m unittest discover -s tests -p test_world_flipper_scoped_equipment.py
python -m unittest discover -s tests -p test_world_flipper_equipment_rules.py
```

Godot行为、归属投影、真实施法和界面检查分别位于`test_equipment_scopes.gd`、`test_equipment_casts.gd`、`test_equipment_ui.gd`，完整入口仍为`./tools/test.sh`。本轮Windows结果与发行包指纹见[验收记录](../reports/world-flipper-equipment/validation.json)，权利状态见[原作素材声明](../assets/worldflipper/NOTICE.txt)。

## 弹头合批与等价验证

运行时将原512×64图集的八个弹头单元，以及其余13件武器的64×64原图，精确复制到2048×64、32列的`ImageTexture`。图集只在运行时构建，原有99张PNG保持。每个弹头仍保留自己的位置、方向、半径缩放和来源帧；63个武器／符文逻辑家族仍存在，600个压力弹头通过同一个`MultiMesh`实际绘制，统计`head_gpu_batches=1`。空帧释放实际弹头实例，满池仍允许1600个；屏内外弹头、拖尾、翼线与弹射环完整保留。

UV着色器同时检查两个实例哨兵，只对标记弹头按整数像素中心取样；没有标记的背景、文字、发光本体、弹射环和其他World画布元素沿用原绘制。主代理已完成12个原生对照：0、1、21、63、600、1600实例，各核对单独弹头与未标记画布内容，旧绘制与新绘制逐像素相同。该证据覆盖上述固定功能样本，没有将其扩大为整段自然战斗或所有World帧完全等同的声明。

尾迹端点使用cursor复用缓冲，保留有效端点、样式和顺序。碰撞求解在没有其他候选竞争时避免重复计算已知交点，并仅在安全的`t=0`最早命中处提前结束。冷却中的技能显示沿用当次已锁定参数，冷却结束后再按当前背包装备计算下一次施放。主代理已对两组各600步进行完整对象池、UID、技能状态及三条随机流对照，模拟状态一致；CPU微基准不作为原生帧率结果。

相关回归入口为`test_projectile_painter.gd`、`test_cosmetic_culling.gd`、`test_trail_readability.gd`及完整`./tools/test.sh`。无窗口检查验证CPU缓冲、家族范围、几何与模拟纯度，真实GPU回读和像素结果由原生窗口独立验证。本轮126套Godot检查及5项诊断累计79,237条断言通过，250项Python检查通过；源码与PCK各34组原生检查通过，42组源码／PCK／真实发行EXE像素及完整状态一致。细节见[源码证据](../reports/world-flipper-equipment/runtime-validation.json)与[优化等价证据](../reports/world-flipper-equipment/optimization.json)。

## 公平压力轮换与运行入口

内容压力补弹使用独立、持续递增的序号轮换21件武器与三类符文，共63个逻辑家族。序号在该压力场景启用时归零，后续补弹继续轮换，避免高消耗家族消失后因存活数偏移反复补入少数类型；正常对局不使用这套压力补弹规则。当前仍保持每步前300敌人、600真实伤害弹体、200掉落，58 FPS与P99不高于33毫秒的门槛，保留原模拟负载。

原生压力新增`--equipment-scopes`，必须同时带`--backpack-skills --hero-skills`。夹具通过真实背包交易额外购买五件新武器，保留主角R与两个合法后排；它提供明确的测试预算，不代表自然对局或真人难度。以下分别为基础阿尔克与五装备莫迪亚迦配置，仅为运行用法，帧率与通过状态由实际输出报告决定：

./tools/run.ps1 --script res://tools/benchmark_dash.gd '--' --backpack-skills --hero-skills --hero=alk --seconds=60 --output=reports/world-flipper-equipment/performance-alk.json
