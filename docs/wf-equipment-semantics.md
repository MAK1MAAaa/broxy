# 日服装备能力语义核对

本文件区分原作事实、可用解码与本作适配。数据固定于 [blead/wf-assets](https://github.com/blead/wf-assets/tree/1d45b529ef078ba9b1f876d4588debd0c8a9a214)，日服1.780.40。能力事实被解码不代表已进入Godot；原作倍率也不能直接替换当前1／2／4阶数值。

当前按完整123列行指纹核准16件装备、35条规则；另外410件装备、851条规则保留unsupported。全部886条原能力与108条增强能力均保留完整行和SHA256。新增语义没有改写游戏装备或覆盖账本，所有解码结果的运行支持仍为`not_claimed_by_extractor`。

## 原始结构

`item/equipment.c10` 指向 `ability/ability_soul`。426件装备对应886行，每行123个字符串；增强装备另有29组、108行126列，保留原值，不能拿123列的位置套用。`equipment.c6` 是图片路径，不是能力DSL。

| 123列表位置，0起算 | 已核对用途 |
| --- | --- |
| c0／c1／c2 | 能力槽／原装备解锁等级／触发模式0瞬时、1持续、2开场 |
| c3:10、c10:17、c17:24 | 三段前置条件，右端不包含 |
| c24:36、c36:43、c43 | 瞬时事件、执行前内容、延迟 |
| c44:82 | 瞬时效果；已核对比例强度在c48／c49，除以100000 |
| c82:94、c94:105、c105 | 持续积累、持续条件、装备者死亡时是否继续 |
| c106:120 | 持续效果；与瞬时效果是不同opcode命名空间 |
| c120:123 | 开场分支 |

旧八件使用瞬时分支。已核对JP事件为0开场／初始、2强化弹射计数、14角色复活、19自身施法、53队伍组别计数；效果32攻击、34技伤、35技能充能速度、55强化弹射伤害、67暗耐下降免疫、70迟缓免疫、209按最大生命损血、211技能槽比例。代码只对有精确来源的装备上下文使用这些名称。

原表解锁等级与本作背包阶级不是同一维度。相同slot出现多个解锁等级时需要核对替换关系，不能逐行盲目累加。占事略决slot1在3级为队长攻击20%，5级改为40%，不是60%。不同slot如悲叹死镰3级的攻击、技伤、回转仍是独立效果。

## 向全部426件扩展的证据边界

不能直接采用现成CN枚举。公开 [CN反编译工具说明](https://github.com/kuronzzhan-droid/startpoint-cn-mod-tools/blob/1d780506b77fcdb3a452655c1b6d01a4398d2e6e/README.md)明确面向国服；其中事件19为回复，而固定JP行19为施法、14为复活。官方[早期试玩JS](https://worldflipper.jp/demo/src/world-flipper.js)静态解码后，旧`AbilitySoulValues.parseAt1`又将施法映射为13、复活为9，而且表结构早于三段前置条件。其原SHA由地形来源登记固定，远程JS没有执行。地区与版本差异均不能忽略。

可采用的增量路径：每件先核对原作ID、完整原行、对应说明、事件主体、作用目标、强度单位与同槽替换；再把该精确上下文加入解码器，并锁完整行指纹。陌生条件、目标、事件、持续模式、增强126列表仍保留unsupported。相同opcode出现在另一装备，不自动构成完整语义已证明，更不自动构成可玩效果。

```powershell
python tools/world_flipper_equipment_rules.py --offline --check
python -m unittest discover -s tests -p test_world_flipper_equipment_rules.py
```

`select_reviewed_rules(item, original_level)`只接受已核对装备和原作1至5级，按slot保留最高已解锁行；它不执行加成、不把本作背包Ⅰ／Ⅱ／Ⅲ阶转成原等级，也不替未核对装备作通用选择。新八件交叉核对页的版本及HTML摘要保存在工具的`ADDITIONAL_FACT_CHECKS`，原数值继续以锁定JP表为准。
